## [2.0.0] - 2026-08-15

A major version because upgrading changes behaviour on the wire, not because anything here was a
redesign. Every change below is defect repair. Most of it was found by deleting a real application
built on this framework and regenerating it from its schema alone — three times — and each time
running the result rather than reading it.

The headline number: a generated application went from **eight manual interventions** between
`foundry new` and a green test suite down to **zero**. Two of those interventions were needed because
the generated application could not start at all.

### Breaking
- **Custom update endpoints answer 404 for an unknown id**, where they answered `200` with a body of
  `false`. Foundry's own scaffold writes `if (entity == null) return false;` — `false` *is* the
  framework's "no such record" — and the endpoint layer serialized it as success. One API reported a
  missing id two ways: generated CRUD returned 404, a custom update on the same id returned 200. Any
  client checking status rather than parsing the body read a failed update as a successful one.
- **Kafka outbox payloads change encoding.** `MongoOutboxQueue` serialized with stock
  System.Text.Json, so an `ObjectId` reached a topic as `{"Timestamp":…,"CreationTime":…}` — both
  members derived from the same four bytes of the id, with the random and counter bytes absent, so
  nothing could reconstruct it. A consumer could not correlate an event to the record it described.
  Ids are now hex strings and enums are names, matching the REST surface. **Any consumer parsing the
  old shape must be updated.** Rows already queued still drain; their ids decode to `ObjectId.Empty`,
  because those bytes were never written.
- **A malformed request body answers 400, not 500.** Model binding runs before any Foundry code, so a
  `BadHttpRequestException` from System.Text.Json fell through to the catch-all. A caller could not
  tell "you sent something I cannot read" from "I am broken", and a 500 invites a retry that can
  never succeed. The response carries the JSON path and the missing property names, without echoing
  the BCL message, which names the application's internal CLR type.
- **The compiler rejects a property declaring both `Encrypt` and `Mask` (FDY3025).** It previously
  honoured the encryption and dropped the mask in silence. A schema relying on that combination now
  fails to compile and must choose one.
- Generated entities, enums and DTOs move into `Entities/`, `Enums/` and `Dtos/` directories.

### Added
- `foundry new` emits `Properties/launchSettings.json`. Without it `dotnet run` — the command the CLI
  prints as step 3 — ran in the Production environment, never loaded the `appsettings.Development.json`
  the scaffolder had just written a signing key into, and died reporting missing authentication
  configuration. The scaffolder created a secret its own run command could not read.
- The CLI ships as a .NET tool (`dotnet tool install -g --add-source artifacts/tool Foundry.Cli`),
  alongside the standalone binary. `dotnet publish` previously failed in *every* configuration —
  `PublishSelfContained` and `EnableCompressionInSingleFile` contradicted each other through a
  non-self-contained `Exe` reference — so there was no way to obtain the CLI except running it from
  a source checkout. All three outputs are now exercised: a plain publish produces a
  framework-dependent single file, `scripts/build-distro.sh` a self-contained one, and `dotnet pack`
  the tool package.
- `foundry schema build` prunes orphans: generated files the schema no longer emits are deleted. Only
  files marked `// <auto-generated/>` are ever removed. `--no-prune` disables it.
- `UrlWhenPresent`, `PhoneWhenPresent` and `EmailAddressWhenPresent`. A generated property is a
  non-nullable `string` initialised to `string.Empty`, and the stock validators reject `""` — so
  declaring `Url` on an optional property made it mandatory, and the only way out was to drop the
  validation entirely.
- `CustomRequestBinder` and `QueryValueBinder`: custom `GET`/`DELETE` requests bind from the route and
  query string. They were constructed as `new TRequest()`, so every property held its type default and
  a declared `GreaterThan MinimumUtilizationPercent` filtered as `> 0` and returned everything.
- `ScaffoldedAppRunnabilityTests`, covering what the existing wiring gate structurally could not: it
  reflects over `AddFoundry*`/`MapFoundry*` names, and an illegal database name, a missing environment
  file and an uncalled generated entry point are not missing registrations.
- `MongoAuditSink`, a durable MongoDB-backed `IAuditSink` writing to an `audit_log` collection, with
  batch validation before insertion so one invalid entry cannot leave a partial write. Opt-in via
  `AddFoundryMongoAuditSink()`.
- `MongoHealthCheck` and `AddFoundryMongoHealthCheck()`, registered with failure status `Unhealthy`
  so an unreachable database answers a readiness probe with 503 rather than 200.
- OTLP and console exporters for `AddFoundryTelemetry`. The endpoint comes from
  `FoundryTelemetryOptions.OtlpEndpoint` or the standard `OTEL_EXPORTER_OTLP_ENDPOINT`; with neither
  set, telemetry stays in-process, which is now a documented choice rather than an accident.
- Generated applications wire the audit sink, the health check and telemetry, map `/api/health`
  unauthenticated, and register the request-telemetry behavior first so one span wraps the pipeline.
- `foundry new` emits a `Dockerfile` and `.dockerignore`. The image packages a published output
  rather than building from source, because the project references the framework by relative path.
- `ScaffoldedAppWiringTests`: fails the build when a public `AddFoundry*`/`MapFoundry*` registration
  is wired into no generated application and carries no documented exemption.
- An `otel-collector` service in `docker-compose.yml` for verifying the telemetry path locally.

### Changed
- `AuditBehavior` renamed to `RequestTelemetryBehavior`. It never wrote an audit entry — it opens the
  OpenTelemetry activity and records metrics. Three documents claiming it emitted audit entries are
  corrected.
- `FoundryTelemetryOptions.ServiceVersion` reads the entry assembly's informational version with
  build metadata stripped, instead of a hardcoded `"1.0.0"`.
- The quick-start guide no longer quotes test counts, which had drifted by an order of magnitude.

### Fixed
- **A conventionally-named project could not start.** The scaffolder defaulted the database name to
  `{ProjectName}Db`, and a dot is idiomatic in a .NET project name and illegal in a MongoDB database
  name — so `foundry new Contoso.Orders.Api` built cleanly, printed READY-TO-RUN, and threw
  `ArgumentException` out of `AddFoundryMongo` before serving a request. Names are now reduced to
  characters MongoDB and Docker both accept. Existing projects are unaffected: `Program.cs` is a
  write-once scaffold and keeps whatever default it was generated with.
- **A schema declaring `Encrypt` got no key**, so the application started and answered 500 to every
  write touching that entity — discoverable only by hitting it. A development key is now generated
  alongside the signing key, and a missing one fails at startup naming the two configuration keys.
  `AesEncryptionProvider` also rejects a raw passphrase with "must be base64 encoded … openssl rand
  -base64 32" instead of a bare `FormatException` raised from inside DI resolution.
- **A POST of an entity with encrypted or masked properties returned an id of all zeroes.** The
  driver stamps the generated id on the instance it is handed, and that instance is a clone produced
  by `EncryptEntityForWrite` — so the caller's entity kept `ObjectId.Empty`, the response returned an
  id for a record stored under a different one, and the audit and revision rows keyed to
  `000000000000000000000000`, leaving an audit trail that could not tell one insert from another.
- **Both caches were keyed without the caller**, so a cached row served across tenants.
  `CallerViewFingerprint` now folds the tenant, subject, roles, groups and `view:` scopes into the
  key, in `CachingBehavior` and `CachedRepository` alike.
- `IWorkflowStateStore` was a singleton holding scoped dependencies — a captive dependency that
  pinned one request's state for the life of the process.
- One rule name used for two methods (`"POST": ["XRule"], "PUT": ["XRule"]`) emitted the stub twice
  into one path, so the surviving class implemented one interface while both registrations were
  emitted: `CS0311` on generated code naming types the author never wrote.
- Generated request records referencing `ObjectId` omitted `using MongoDB.Bson;` — `CS0246` on a
  freshly scaffolded project.
- The generated Kafka consumers had no producer and no outbox writer registered, so an application
  could receive events and send none, and the outbox collection was never created.
- Declared `Unique`, `Indexed` and `TextIndex` reached no database: `IndexVerification` was generated
  and never called, so uniqueness went unenforced and the indexed queries were collection scans.
- A malformed query-string value answered 500 rather than 400. This file has `using FluentValidation;`,
  so the handler's branch bound to that `ValidationException` while the binders throw
  `System.ComponentModel.DataAnnotations.ValidationException` — two types one using-directive apart.
- `foundry sdk` wrote a flat `foundryClient.ts` for every project, so generating SDKs for two
  services into one directory silently overwrote the first. The name now comes from the schema
  namespace, `-o` is documented, and a missing output directory is created.
- The framework's own `docker-compose.yml` published kafka-ui on 8080, so `docker compose up -d`
  failed for the whole command whenever anything else held that port — the stack read as broken when
  the only thing that could not start was an optional web UI. It publishes on 8090, and the three
  images still floating on `:latest` are pinned.
- The scaffolded `docker-compose.yml` no longer floats on `:latest`. It stopped coming up when
  `bitnami/kafka:latest` was withdrawn, and because Compose aborts the whole pull set on a failure,
  MongoDB did not start either — so step 2 of the printed quickstart took step 3 down with it.
- Both MongoDB services in `docker-compose.yml` now set `nofile` to 64000. Without it `mongod`
  exhausts file descriptors during a long run and WiredTiger panics, which presents as unrelated
  connection-refused failures across every suite still running.

### Removed
- `templates/Foundry.Api.Template`, a second scaffolding path that had stopped compiling, was absent
  from `Foundry.slnx` so no CI job built it, and registered a stub `ICurrentUserContext` that
  silently disabled ownership filtering and masking. `foundry new` is now the only path.

## [1.0.0] - 2026-08-08

### Added
- LICENSE (Apache-2.0) and license metadata across packages.
- Configurable group-claim type names for JWT authentication (`FoundryAuthenticationOptions.GroupClaimTypes`).
- A schema-validation warning when a workflow transition or state declares no roles.
- Bounded (one-level) recursive redaction of sensitive nested workflow payload properties.
- A `WorkflowCommandTypeRegistry` replacing assembly-wide reflection scanning for `InternalApi` workflow actions.
- `foundry token mint`: mints a self-issued HS256 JWT from the same `Authentication__Jwt__SigningKey` a deployment already configures, for local dev, CI, and service-to-service use.
- Role-based masking entitlement: `[SensitiveData]` and `[PiiData]` both gained a `Roles` property, so a caller can unmask a category by role as well as by `view:{category}` scope.
- `FoundryMongoOptions.AllowUnauthenticatedFullReads`, the named opt-in that restores pre-1.0 read behavior for a deployment with a genuine no-caller use case.

### Changed
- Bulk-write optimistic-concurrency filters (`BulkUpdateManyAsync`, `BulkUpdateAsync`) now scope by tenant and owner, matching every single-document write path.
- The archival sweep now processes documents in bounded batches instead of loading a whole entity type into memory and archiving a full year in one transaction.
- `foundry version` now reports the actual assembly version instead of a hardcoded string.
- An unauthenticated caller reading an owner-scoped entity now reads zero rows by default, not every row. See `AllowUnauthenticatedFullReads` above for the opt-out.

### Fixed
- `foundry version` and `foundry doctor` could report different version numbers for the same build; they now share one source of truth.
- The `distro-binary` CI job could fail with `'<hash>' is not a valid version string` when built from an untagged commit, because `git describe --tags --always` never fails and silently returned a bare commit hash instead of a version.
